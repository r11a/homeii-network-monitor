# HOMEii 8 — local Zabbix workspace

Latest ruling: the user requested one automatic add-on and a testable preview. The deployment below is superseded by a single image bundling Zabbix/PostgreSQL with HOMEii, on separate beta slug/port 8384. Advanced IT tooling, automatic HA card installation, offline installer and load qualification remain explicitly deferred in DOCS.md. The existing installation remains on main with its own data.

User-approved direction: preserve and back up 7.5.4, create a Zabbix-based version, publish to the repository. All routine operation uses clear forms, no JSON/YAML. Local operation must not depend on Internet. Target thousands of devices; capacity remains a measured deployment property, not a release claim.

Approach: integrate a separately deployed Zabbix 7.0 LTS engine via its API; retain the existing application and database as a reversible legacy workspace. Rejected rebuilding an enterprise collector from scratch; LibreNMS remains an alternative but is not another simultaneous authority. The new workspace owns presentation; Zabbix owns hosts, measurements and incidents. Stable Zabbix host IDs are never replaced by IP identifiers. Discovery proposals require explicit approval; no blind auto-add actions.

Deliverables: bundled local Docker Compose deployment, bootstrap without visiting Zabbix, offline image preparation/launch tools; visual connection setup for external servers; authenticated dashboard, paginated/filterable inventory, host detail with measured 24h history and visible gaps, discovery review, host creation, acknowledge and check-now; local HA bridge/cards using stable IDs. Hebrew/English and existing login roles remain. A source/refs backup and remote backup tag precede edits. Local test databases are not represented as live installation backups.

Constraints: preserve legacy SQLite and routes. Secrets are server-side files, never in settings exports or browser responses. No public access to new engine APIs. Stale or absent probes never become green. All fonts/assets bundled. Runtime external notifications are optional and unavailable without their network. Deployment installation requires preloaded images for offline sites. No Docker runtime or live Zabbix is available in this workstation: verify contracts using a real local HTTP fixture, run repository suites, add container integration CI; document live deployment/capacity validation limits.

Initial scope: ICMP profile with visual onboarding; existing Zabbix hosts and incidents visible, no unsupported claim of universal SNMP model recognition. Native discovery requires engine reachability to each network. Imported engine host IDs remain stable across address changes; uncertain discovered identity is not merged automatically.
